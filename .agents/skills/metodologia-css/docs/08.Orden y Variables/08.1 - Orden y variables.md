# Orden del documento y variables CSS

Orden fijo del archivo (ver [[05.1 - Flujo de trabajo]]):

1. **Tipografías** (`@font-face` / carga de fuentes). Si se declaran, al inicio,
   antes de `:root`.
2. **Variables globales** (`:root { ... }`).
3. **Tokens de breakpoints** (`@custom-media`, solo con PostCSS) y **animaciones**
   (`@keyframes` con prefijo `a-`). No afectan a la cascada.
4. **Modificaciones globales de etiquetas** (`html`, `body`, `a`, `h1`, `p`, …),
   después de `:root` y antes de los temas.
5. **Temas (`t-`)**, siempre antes que los componentes.
6. **Componentes (`c-`)**: variables al inicio → base/variantes/elementos/estados
   → media queries.

## Reglas

- Los `.t-` son transversales: van siempre **antes** de los `.c-`, nunca después.
- Cada media query va **después** del bloque base al que afecta, no agrupada al
  final del archivo. No cambia la especificidad, pero sí puede cambiar el orden
  de origen entre reglas de igual especificidad. Conserva el orden global desde
  componentes genéricos a especializados; por ejemplo, `c-textofoto` antes de
  `c-textblock`.
- Las variables van al inicio de su ámbito: globales en `:root`, por componente
  al inicio del componente.

## Variables

Globales:

```css
:root {
  --color-primario: #1f5fbf;
  --radio-base: 12px;
}
```

Por componente (formato):

```css
.c-ejemplo,
.c-ejemplo * {
  /* Tus variables de componente aquí */
  --c-ejemplo-padding: 1rem;
  --c-ejemplo-radio: var(--radio-base);
}
```

En los breakpoints, modifica solo las variables cuando sea suficiente para el
rediseño responsive; esto no restringe incluir otros ajustes.

```css
.c-ejemplo,
.c-ejemplo * {
  --c-ejemplo-padding: 1rem;
}

@media (min-width: 1024px) {
  .c-ejemplo,
  .c-ejemplo * {
    --c-ejemplo-padding: 1.5rem;
  }
}
```

Convención de nombres: `--c-[bloque]-[propiedad]`.
